# Development documentation

`PROJECT_PLAN.md` defines challenge rules; `CONTEXT.md` defines domain terms; `shared/schema/common.schema.json` defines the development data contract. `docs/workstreams.md` maps the integrated modules.

Record meaningful integration steps in `docs/progress/integration.md`. The three developer-named logs remain as historical records from the parallel workspaces. For each step, record the date, status, changed files or interfaces, reason, checks and results, open assumptions, next action, and commit or pull request when available. Preserve factual results from failed experiments.

If a change alters a shared field, constraint, formula, or rule interpretation, update the authoritative source in the same change. The progress log is a record of work, not the sole source of a rule.
